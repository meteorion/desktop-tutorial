# 自适应引导式 AI 面试助手 —— 产品设计文档

- 状态:V1 草案(已完成头脑风暴,待评审)
- 日期:2026-09-14

## 1. 产品概述

### 1.1 产品定位

面向 C 端个人求职者的自适应引导式 AI 面试准备工具。核心价值主张:把"要面试什么岗位"到"能自信参加真实面试"之间的过程,拆解成一条可执行、可衡量、由 AI 动态调整的学习路径,而不是让用户自己去网上找题库刷题。

### 1.2 目标用户画像

正在求职或计划跳槽的个人求职者,包括:

- **应届生**:缺乏实战经验,需要系统性査漏补缺,从零建立岗位所需知识框架。
- **在职跳槽者**:已有一定经验,需要针对性补强和查漏,避免重复学习已掌握内容。

两类用户共享同一套产品机制,差异主要体现在简历解析出的学习起点不同。

### 1.3 核心用户旅程(主循环)

```
①设定目标 → ②(可选)导入简历 → ③生成面试计划 → ④确认/微调计划
      → ⑤学习(题库练习 + 知识卡片) → ⑥答题即时评估,更新知识点掌握度
      → ⑦系统动态调整后续每日计划 → ⑧用户查看掌握进度看板
      → (掌握度达阈值) ⑨解锁模拟面试 → ⑩AI 模拟面试(文字对话)
      → ⑪AI 审核面试表现并给出建议 → ⑫建议回流,针对性强化薄弱知识点 → 回到⑤
```

这是一个"学习 - 评估 - 调整 - 验证"的闭环:模拟面试不是终点,而是对学习效果的验证节点,其结果又反过来指导下一轮学习重点。这个闭环设计是整个产品的核心机制。

## 2. 功能模块设计

### 2.1 目标设定与简历导入

用户从标准岗位库中选择目标岗位(如"后端开发-Java""产品经理-B端"),设定目标薪资范围。可选上传简历(PDF/Word),AI 解析工作经历、项目经验、技能标签、教育背景,自动完成两件事:

1. 推荐/预填目标岗位和合理薪资区间;
2. 与目标岗位的知识点框架做差异比对,识别用户已具备和缺失的能力项,作为计划生成的初始输入。

未导入简历的用户默认按岗位标准框架从零开始评估。简历解析置信度低或信息不足时,AI 需明确标注"以下为推测填写,请确认",不静默填入,避免误导用户设定不合理的薪资目标。

### 2.2 面试计划生成(规则引擎 + LLM 混合)

- **规则引擎侧**:每个标准岗位对应一份结构化知识点大纲,区分「核心知识点」与「普通知识点」(核心点用于后续解锁判定),每个知识点关联难度、权重、预计学习时长。
- **LLM 侧**:结合简历差异分析结果,裁剪/排序知识点优先级,生成每日学习任务的具体描述、初始预计周期(如"14 天计划"),并生成计划说明文案(如"根据你的经验,我们优先安排系统设计相关内容")。

选择该混合方案而非纯 LLM 端到端生成或纯规则引擎,原因是:结构化知识点框架保证了"掌握度"量化和解锁机制有可靠的数据基础,同时 LLM 负责的个性化生成保留了产品的灵活性和 AI 调性。

### 2.3 计划确认

系统展示计划总览(周期、每日任务量、知识点覆盖),用户可对个别知识点/任务做增删或调整节奏后确认。确认后计划进入执行状态,生成第一天的具体任务。

### 2.4 学习模块

两种内容形式:

1. **题库练习**——按知识点生成结构化面试题(单题作答),提交后 AI 即时点评正确性、给出参考答案和改进建议。
2. **知识卡片**——短内容讲解卡片,用于快速补盲,不计入掌握度评分,仅作为练习前的预习材料。

### 2.5 评估与掌握度计算

采用「知识点维度扫描」方式衡量掌握进度:每个知识点独立维护一个掌握度分数,由该知识点下历次练习题的正确率、题目难度加权综合计算得出。掌握度随新的练习结果持续更新(非一次性判定),用户可在看板中看到"哪些知识点还薄弱"。

### 2.6 动态计划调整

系统在每次任务提交后重新评估,依据三类信号联动调整后续计划(三者共同输入到"次日任务生成"逻辑,而非相互独立生效):

1. **掌握度信号**:低于阈值的知识点自动插入更多同类练习;已掌握内容减少重复或转为复盘。
2. **进度/时间投入信号**:实际完成进度偏离预期(拖延或超前)时,重新平摊剩余日程,增减每日任务量。
3. **主观反馈信号**:用户可对题目反馈"太难/太简单",结合客观正确率修正后续题目难度分布。

用户长期未完成任务(如连续多日零完成)时,触发计划重新平摊,而非让逾期任务无限堆积在同一天。

### 2.7 掌握进度看板

以知识点为维度的可视化进度展示(如雷达图/进度条列表),显示整体掌握度、各知识点掌握度、已完成任务量,以及与解锁模拟面试所需门槛的差距。

### 2.8 模拟面试解锁与执行

**解锁条件**:核心知识点全部达标(如 ≥70%)且整体平均掌握度达到阈值(如 ≥80%),两者需同时满足,防止个别薄弱核心知识点被整体均值掩盖。

**执行方式(MVP)**:文字对话式模拟面试。AI 基于目标岗位和用户掌握度较低的知识点动态出题,支持多轮追问(根据用户回答追问细节,而非固定题单)。

模拟面试题目不与学习阶段做过的原题重复,需要去重/变体机制,避免用户"背题"通过模拟面试而非真正掌握。

解锁后为永久可用,不因后续掌握度下降而重新锁定,但看板会持续提示掌握度变化,避免过度惩罚用户的探索行为。

### 2.9 AI 审核与建议

面试结束后,AI 从以下维度对本次面试逐题及整体评分,并生成文字总结报告(亮点、不足、针对性改进建议):

1. **专业知识/技能准确度**
2. **表达与逻辑结构**
3. **非语言信号(语调/自信度)**——数据模型中预留字段,但 MVP 阶段(纯文字模拟面试)不产出评分,待语音/视频模态上线后启用。

报告中的薄弱项会反哺 2.6 的动态调整,生成新一轮针对性学习任务,形成闭环。

## 3. 数据模型(概念层)

| 实体 | 关键字段 | 说明 |
|---|---|---|
| 用户 User | 目标岗位、目标薪资、简历摘要 | MVP 限制单一进行中岗位计划 |
| 岗位 Position | 岗位名称、知识点大纲(有序)、核心知识点标记 | 标准岗位库,后台维护 |
| 知识点 KnowledgePoint | 所属岗位、名称、权重、难度、是否核心 | 掌握度计算和解锁判定的最小单元 |
| 学习计划 Plan | 用户、岗位、周期、状态(草稿/确认/执行中/已解锁模拟面试) | |
| 每日任务 DailyTask | 所属计划、日期、任务列表(题目/卡片引用)、完成状态 | 动态调整时被重新生成/覆盖 |
| 题目 Question | 所属知识点、题型、内容、参考答案 | LLM 生成后持久化复用,降低重复生成成本 |
| 作答记录 Attempt | 用户、题目、作答内容、AI 点评、得分 | 掌握度计算的原始数据源 |
| 掌握度记录 Mastery | 用户、知识点、当前分数、更新时间 | 按 Attempt 滚动重算 |
| 模拟面试会话 MockInterviewSession | 用户、岗位、对话记录(多轮) | |
| 审核报告 ReviewReport | 所属会话、各维度得分、总结建议、关联的薄弱知识点 | 反哺下一轮 DailyTask 生成 |

## 4. 关键流程

**动态调整闭环**

```
用户提交作答 → 更新 Attempt → 重算相关 KnowledgePoint 的 Mastery
   → 触发次日 DailyTask 生成规则(掌握度信号 + 进度信号 + 主观反馈信号)
   → 若 Mastery 汇总达到解锁阈值 → Plan 状态置为"可解锁模拟面试"
```

**模拟面试与反馈闭环**

```
用户发起 MockInterviewSession → AI 依据低掌握度知识点动态出题/追问
   → 会话结束 → 生成 ReviewReport(评分 + 建议)
   → 建议中的薄弱知识点写回 KnowledgePoint 优先级 → 影响下一轮 DailyTask 生成
```

## 5. 边界情况

- 用户未导入简历:知识点起点全部按"未掌握"处理,不影响主流程,只是个性化程度降低。
- 简历解析置信度低/信息不足:AI 明确标注"以下为推测填写,请确认",不静默填入。
- 用户长期未完成任务:触发计划重新平摊,而非无限累积逾期任务堆积在同一天。
- 已解锁模拟面试后掌握度下降:解锁状态永久保留,不重新锁定,仅看板提示变化。
- 模拟面试题目需与练习阶段去重/变体,防止"背题"通过。

## 6. 成功指标(建议)

- **计划完成率**:确认计划的用户中,完整走完计划周期的比例。
- **知识点掌握度提升曲线**:用户从计划开始到解锁模拟面试的平均掌握度增长速度。
- **模拟面试解锁率与解锁耗时**:多少比例用户能达到解锁门槛,平均花费多少天。
- **模拟面试后的学习回流率**:收到 AI 建议后,用户是否针对薄弱项继续学习(而非流失)。

## 7. 暂不实现范围(明确排除,避免范围蔓延)

- 语音/视频模拟面试及非语言信号分析(架构预留,不在当前设计范围实现)。
- B 端多租户、机构管理后台。
- 多岗位并行学习计划(MVP 限制单一进行中计划)。
- 真实招聘对接、简历投递等求职闭环功能。
