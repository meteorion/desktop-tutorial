## 1. 视觉风格

整体风格定为**游戏化激励**:渐变亮色(主色 #6C5CE7 紫 → #00D2A8 青绿)、圆角卡片、进度条/连续打卡/emoji 图标,强化"每天学一点、肉眼可见在变强"的坚持感和成就感,区别于纯工具型 App 的冷静克制风格。这个方向是在专业简洁 / 游戏化激励 / 极简暗色科技感三个方向中比较选出的。

## 2. 信息架构与导航

底部 5 个 Tab:

```
🏠 首页(掌握进度看板)   📘 学习(每日任务)   💬 自由学习   🎤 模拟面试   👤 我的
```

- **首页**是默认落地页,承担"今天该干什么 + 我进展如何 + 离模拟面试还差多少"三件事,是产品文档 1.3 核心循环中⑧看板与⑨解锁判断的载体。
- **学习**入口直接进入当日任务队列(题库练习为主,穿插知识卡片)。
- **自由学习**入口独立于每日任务,对应产品文档 2.5。
- **模拟面试**入口在未解锁时显示锁定态引导(说明还差多少掌握度),解锁后展示"开始新的模拟面试"和历次报告列表。
- **我的**放置目标岗位/薪资设置、简历重新导入、LLM Provider/API Key 配置(对应架构文档 app_settings)、数据备份导出。

## 3. 关键界面(HTML 原型)

以下 9 个界面(含 3.8/3.9 两个补充状态)覆盖 5 个 Tab 的主要内容、产品核心循环中最高频的节点,以及审核发现的几个高频"非理想路径"状态,已做成可在浏览器直接打开的静态 HTML 原型(见文档顶部链接),下面是每个界面的设计说明。

### 3.1 首页 / 掌握进度看板([dashboard.html](ui-mockups/dashboard.html))

- 顶部渐变卡片:目标岗位、连续学习天数(打卡激励)、整体掌握度环形进度 + 距解锁模拟面试的差距文案。
- 中部知识点列表:每个知识点一条卡片,进度条颜色随分数区间变化(红→黄→绿),核心知识点带「⭐核心」标记,呼应产品文档 2.9 的双门槛解锁条件,让用户直观理解"平均分够了但核心点不够也不能解锁"。
- 模拟面试入口:未解锁时以虚线卡片 + 🔒 呈现,并明确指出卡点是哪个知识点(而不是笼统的"还没达标"),降低用户的挫败感。
- 底部大按钮直接跳转到当日未完成任务,减少"看完进度还要再找入口"的路径。

### 3.2 学习 Tab · 今日任务清单([task-list.html](ui-mockups/task-list.html))

- 顶部沿用渐变卡片展示"今日任务完成数/总数"和进度条,与首页的整体掌握度环区分开——这里是"今天"的进度,不是"全局"进度。
- 任务列表混排题库练习和知识卡片两种类型(图标区分:📘 练习题 / 🗂 知识卡片),已完成项保留完整饱和度的绿色对勾、仅文字变灰加删除线(而非整行降低透明度,避免"已完成"被误读成"不可用"),当前该做的一项用主色描边高亮,未开始项弱化处理——一眼看出"现在该点哪个"。
- 核心知识点的任务带「核心」标签,呼应首页解锁条件里对核心知识点的强调,保持全局一致的视觉语言。
- 点击列表项跳转到 3.3 的题库作答页(知识卡片项跳转到卡片阅读页,未在本轮设计)。

### 3.3 每日学习任务(题库作答)([daily-task.html](ui-mockups/daily-task.html))

- 顶部题号 + 进度条,给出"还剩几题"的确定性反馈。
- 题目卡片标注所属知识点及是否核心,呼应 2.7 动态调整逻辑对核心知识点的优先级。
- 提交后切换为反馈态:圆形得分 + 一句话简评 + 参考答案要点,而不是大段文字堆砌,降低用户阅读成本。
- 「🚩 标记有误」是低视觉权重的次要入口,对应产品文档 5. 边界情况中的 LLM 内容质量兜底机制,不喧宾夺主但保证可发现。

### 3.4 自由学习([free-learning.html](ui-mockups/free-learning.html))

- 顶部说明文案强调"随时回顾,不占用今日任务进度",与 3.2/3.3 的每日任务在心理上做区隔,避免用户误以为自由学习也计入当日任务量。
- 核心是「AI 为你选了 XX 知识点做回顾」的提示卡片,体现产品文档 2.5 的「AI 主导回顾式问答」而非用户自由发散提问;卡片右侧「换一个」允许用户跳过本次系统选择的知识点。
- 不显示题号/进度条(区别于 3.3 的每日任务),强化"开放式、无压力"的使用场景定位。
- 作答与反馈交互复用 3.3 已定义的提交/点评组件,不重新设计一套。

### 3.5 模拟面试对话页([mock-interview.html](ui-mockups/mock-interview.html))

- 整体沿用品牌渐变色但克制使用(仅顶部条),对话区回归朴素的聊天气泡样式,避免面试这种"正式场景"被过度游戏化冲淡严肃感。
- AI 追问的消息带「追问」标签,让用户清楚意识到这是同一话题的深挖,而不是新问题,呼应产品文档 2.9 的多轮追问机制。
- 输入中显示打字指示(三个点),给用户"AI 正在组织语言"的等待反馈。
- 「结束面试并生成审核报告」常驻底部,用户可随时主动结束,不强制走满固定轮数;这个操作不可逆(直接生成最终报告),点击后需二次确认弹窗("确定要结束吗,已进行 N 轮"),避免误触。

### 3.6 AI 审核报告页([review-report.html](ui-mockups/review-report.html))

- 顶部综合得分与"比上次 +6"的趋势对比,呼应产品文档 2.9 新增的历次模拟面试得分趋势追踪。
- 维度得分区分「有数据的维度」和「敬请期待」的非语言信号维度(灰显 + 弱化,而非隐藏),让用户知道这个能力以后会有,不造成"功能缺失"的误解。
- 亮点/不足/建议用三张独立卡片而非一段长文本,便于用户快速扫读定位重点。
- 底部 CTA 直接把"薄弱知识点"接回学习流程,是产品文档 2.6→2.7→2.10 反馈闭环在界面上的具体落点,报告页不是终点而是下一轮学习的起点。

### 3.7 我的([profile.html](ui-mockups/profile.html))

- 分三组信息:求职设置(目标岗位/薪资、重新导入简历)、AI 服务(LLM Provider、API Key 配置状态)、数据(导出备份/从备份恢复),对应架构文档的 app_settings 表和第 8 节的备份/迁移设计。
- 列表行不使用右侧箭头图标引导跳转(经视觉评审去除),用页面顶部一行「以下设置项均可点击进入编辑」的说明文字替代箭头传达可点性,分组卡片的留白/阴影表达层级,视觉更干净,同时不完全丢失可点击的提示。
- API Key 状态用「已配置 ✓」的文字+颜色直接反馈配置结果,不需要额外跳转才能确认。

### 3.8 我的 · API Key 未配置态([profile-unconfigured.html](ui-mockups/profile-unconfigured.html))

- 这是绝大多数用户**第一次打开 App 时会看到的真实状态**(架构文档要求用户手动配置 Key,见架构文档 7),而不是一个边缘情况,因此单独设计而不是留白。
- 页面顶部用橙色警示卡片说明"配置后才能生成计划、批改作答、进行模拟面试",直接给出配置入口,而不是让用户自己摸索为什么其他功能都用不了。
- AI 服务分组里「LLM 提供商」显示"未选择"、「API Key」显示醒目的红色"未配置",与 3.7 已配置态的绿色"已配置 ✓"形成清楚的状态对比。

### 3.9 模拟面试 Tab 落地页([mock-interview-tab.html](ui-mockups/mock-interview-tab.html))

- 3.5 的对话页只是"进行中"这一个状态,本屏补齐 Tab 本身的两个入口状态:**未解锁**(锁定卡片 + 差距文案 + "去学习"引导按钮,复用首页 3.1 已有的锁定卡片视觉)和**已解锁**("开始新的模拟面试"大按钮 + 历次报告列表)。
- 历次报告列表按时间倒序展示每次的综合得分和相对上次的涨跌,是产品文档 2.9 新增的"历次模拟面试得分趋势"在界面上的落点;点击某一条跳转到该次的 3.6 审核报告页。

## 4. 非核心界面(文字说明,未做视觉稿)

## 5. 设计系统基础

### 5.1 颜色

| 用途 | 颜色 |
|---|---|
| 主品牌渐变 | `#6C5CE7`(紫)→ `#00D2A8`(青绿) |
| 主按钮/强调 | `#6C5CE7` → `#8E7CF7` 渐变 |
| 掌握度-低(需加强) | `#FF6B6B` → `#FFD93D` 渐变 |
| 掌握度-中 | `#FFD93D` → `#FFB13D` 渐变 |
| 掌握度-高(已掌握) | `#00D2A8` → `#00B894` 渐变 |
| 页面背景 | `#FAFAFC` |
| 卡片背景 | `#FFFFFF` |
| 正文 | `#222` / `#333` |
| 次要文字(需可读,非纯装饰) | `#6b7280`(说明文字)/ `#767b87`(分组标签、次级 Tab 文字) |
| 弱化文字(已完成/历史项等刻意降权内容) | `#8a8fa3` / `#9aa0ab` |
| 禁用/占位 | `#EEE` / `#F0F0F0` |
| 警示态 | 背景 `#FFF4E5` + 文字 `#8A5A00`(未配置提醒);背景 `#FFF0F0` + 文字 `#C0392B`(请求失败) |

> 说明:之前的 `#999`/`#AAA`/`#BBB` 用作正文/说明文字时,在白底上对比度不足 3:1,低于正文常见的 4.5:1 可读性门槛,已统一替换为上表的次要文字色阶;首页整体掌握度环形进度的填充色也从与"掌握度-低"共用的黄色 `#FFD93D` 改为白色,避免和知识点列表的红黄绿掌握度分级语义冲突(环形进度表达的是"已完成比例",不是"警示")。

### 5.2 组件规范

- **卡片**:圆角 12–14px,阴影 `0 1px 3px rgba(0,0,0,.06)`,内边距 12–16px。
- **进度条**:高度 6–8px,圆角为高度的一半,底色 `#EEE`,填充色按 5.1 的掌握度分级取色。
- **主按钮**:圆角 12px(常规操作)或 20px(胶囊形,用于聊天输入发送等强调操作),渐变填充,白色加粗文字。
- **标签/Pill**:圆角 10–12px,浅色底(如 `#FFF1D6`)+ 深色文字(如 `#B8860B`),用于"核心知识点""追问"等状态标记。
- **聊天气泡**:AI 消息左对齐、白底、左下角尖角;用户消息右对齐、主色底、右下角尖角——是模拟面试和自由学习两个对话式界面共用的组件。

### 5.3 AI 请求状态([ai-request-states.html](ui-mockups/ai-request-states.html))

所有触发 LLM 调用的操作(提交作答、自由学习换一题、生成计划、解析简历等)统一复用这一组状态,而不是每个场景各画一套:

- **加载中**:主按钮渐变色降低饱和度(视觉上"变浅"表示不可再次点击)+ 白色旋转圈 + 动作性文案(如"AI 正在批改…"),而不是把按钮换成通用的转圈图标,让用户仍能读到"系统在做什么"。
- **失败**:内联卡片(浅红底 + 红字)出现在原操作位置附近,附带「重试」按钮;用户已输入的内容(如作答文本)保持不变、不清空,呼应架构文档的失败重试策略(架构文档 6)。

## 6. 待细化项

- 目标设定 / 计划确认两个非核心界面仍只有文字描述,需要时可复用现有关键界面的浏览器原型流程继续细化。
- 知识卡片(2.4 的第二种学习内容形式)的阅读页尚未设计具体样式,3.2 任务清单里点击知识卡片项之后的页面留待补充。
- 非语言信号维度上线(语音/视频模态)后,审核报告页(3.6)的"敬请期待"态需要替换为真实数据展示方案。
- 「我的」页去掉箭头后用文字提示替代可点性线索(3.7),这是一个折中方案,如果用户测试中发现文字提示仍不够明显,可考虑改为整行按压态的背景色变化。
